# Jobs that CI runs and `make ci-local` cannot.
#
# Format: job-id<TAB>reason. A bare job id is rejected; the reason is the point.
# Every entry here is a hole in "green locally means green in CI", so each one
# has to be worth the hole.
#
# The bar: a job belongs here only when reproducing it locally is impossible
# rather than merely inconvenient. Needing a credential, a hosted service, or a
# machine of another kind is impossible. Being slow is not.

build	Builds the release binary for one target on that target's own runner (release.yaml): Linux on x86_64 and arm64, macOS on Apple silicon, for Apple silicon and Intel. Not reproducible from ci-local, which runs on one machine of one kind; what it compiles is compiled and tested there by `make build` and `make test`, and the Linux binary for that machine's architecture by `make smoke-linux`, inside Docker. It runs on a tag, on every pull request (for the smoke jobs, which are required checks) and by hand, and publishes nothing but on a tag.
publish	Publishes a tag's binaries as a GitHub release (release.yaml). Not reproducible locally by design: it needs the repository's token, and a local target that published would mean anybody could release from a laptop. It runs only on a tag, after every `build` and every smoke job (`smoke-linux`, `smoke-macos`).
close	Thanks a pull request from outside the organisation, points it to issues and closes it (outside-pull-requests.yaml). Not reproducible locally by design: it acts on who opened a pull request and on GitHub's own view of whether they are inside this organisation, neither of which exists on a laptop. It checks nothing and gates nothing.
authority-macos	`meridian authority trust` on a real Mac, as install.sh runs it at a terminal, then `uninstall` (authority-macos.yaml). Reproducible on a Mac as `make e2e-authority-macos MERIDIAN_E2E_CHANGES_THIS_MAC=yes`, but not from ci-local: it needs macOS, and it changes the machine's keychain, launchd's environment for apps and its LaunchAgents, which a gate run on every push must never do to a person's machine. It runs on a tag and by hand, and gates nothing on main.
licence	Asks anyone outside the organisation who writes on an issue to agree, once, to the suggestion licence (licence.yaml, the action in .github/actions/licence-check). Not reproducible locally by design: it acts on GitHub's issue events and on GitHub's view of who is inside the organisation, neither of which exists on a laptop. Its decisions are tested in meridian-core by `make licence-check-test`, which its ci-local runs. It checks nothing and gates nothing.
smoke-macos	Each macOS release binary run on each macOS runner GitHub offers inside the supported window (ruling 1033), Apple silicon and Intel: tests/smoke/run.sh's `--version`, `status` against a stand-in kubectl and helm, and `plugin new` then `plugin check` (release.yaml). Not reproducible from ci-local, which runs anywhere and in Docker: it needs macOS, of several majors and both architectures, which no one machine is. The same script runs on Linux inside ci-local, as `make smoke-linux`; on a Mac it runs by hand as `sh tests/smoke/run.sh <version> <target>` with the binary first on PATH. It runs on every pull request, as a required check, on a tag before `publish`, and by hand.
